# Repository instructions

The VS Code extension for CRBasic, a client of the opencrbasic language server
([open-crbasic](https://github.com/UtrechtUniversity/open-crbasic), `python -m opencrbasic.lsp`).
It is MIT licensed and published to the Visual Studio Marketplace. Later it will also offer
logger actions (flash a program, collect data) backed by
[open-loggernet](https://github.com/UtrechtUniversity/open-loggernet).

Priorities: correctness, evidence, simplicity, minimal scope, maintainability.

## Layout

| Path | Contents |
|---|---|
| `src/*.ts` | The client. Logic that needs no `vscode` import lives in its own module so `node:test` can load it. |
| `src/test/` | `node:test` unit tests; they do not start VS Code. |
| `syntaxes/crbasic.tmLanguage.json` | Generated by open-crbasic's `tools/gen_grammar.py`; never edit by hand. |
| `package.json` | Manifest, settings and commands. |

Settings under `contributes.configuration` mirror the server's keys; open-crbasic's
`tests/lsp/test_server.py` checks them when this repository is checked out next to it. Change a
setting here and in the server together.

## Evidence

Never report a test or editor result that was not observed. Behaviour inside VS Code is a host
check: say whether it was run, on which OS and VS Code version.

## Checks

```bash
npm ci
npm run lint        # ESLint with typescript-eslint
npm test            # tsc --strict, then node:test
npx vsce ls         # what the package would contain
uvx pre-commit run --all-files
```

## Releases

`main` publishes to the Marketplace when `version` in `package.json` is new. Bump only when the
human asks for a release.

## Version control

Never create a merge commit; integrate with rebase. Commit only when asked. Do not use destructive
reset or checkout commands without explicit approval.
